## 一、 背景与业务起因

1. **现状与痛点**：
   - 光遇 BWiki 的「复刻计时器」板块用于帮助玩家统计拥有复刻先祖与永久光之翼的数量；
   - 原先玩家需要面对上百位先祖手动逐一点击打勾，查找繁琐且极易漏勾、错勾；
   - 攻略组此前尝试通过指引玩家手动复制长 JSON 并粘贴导入，操作门槛高、转化率低。
2. **权限与协同**：
   - 2026-11-25 17:43，攻略组负责人为 VincentZyu（UID: `34318934`）开通了 BWiki 的全站管理员 (`sysop`)、界面管理员 (`interface-admin`) 与 Widget 编辑权限 (`editwidgets`)，标记身份为“技术人员”。
   - 目标：将网易大神光翼查询能力无缝接入到复刻计时器中，实现一键查询、自动点亮先祖与可视化分类展示。

## 二、 后端基础设施改造（双线 HTTPS 与安全加固）

为保证 Bilibili 前端页面顺利请求 API，进行了端到端的基础设施重构：
1. **双线并行架构**：
   - **生产主线（推荐）**：`https://cf-guangyi.vincentzyu233.cn`（套用 Cloudflare 橙色云，100% 隐藏源站 IP，边缘托管 HTTPS，提供基础抗 DDoS 防护）；
   - **备用线路（直连）**：`https://guangyi.vincentzyu233.cn`（国内阿里云深圳机房灰云直连，低延迟回退通道）。
2. **CORS 跨域支持**：
   - 在云服务器 Nginx 反代层全局注入 `Access-Control-Allow-Origin: *`，彻底解决浏览器跨域拦截问题。
3. **敏感端点拦截保护**：
   - 公网对 `/refreshToken` 强制拦截并返回 `403 Forbidden`，防止爬虫恶意刷登录态；业务端点 `/queryGuangyi` 与 `/checkhealth` 保持完全畅通。

## 三、 前端组件设计规划（参考 Koishi 插件视觉规范）

参考 `koishi-plugin-wydashen-guangyi-query` 插件出图风格，将原先单调的输入框重构成功能完备的光翼收集交互看板：

1. **顶部数据概览 (Overview)**：
   - 玩家角色 ID 徽章；
   - 总光之翼收集数、地图光之翼进度、先祖永久光翼进度；
   - 当前翼数预测与下一阶段差距。
2. **地图光翼分类网格 (Map Grid)**：
   - 划分：晨岛、云野、雨林、霞谷、暮土、禁阁、暴风眼/伊甸、各季节先祖；
   - 已收集项高亮为光遇暖金色发光胶囊标签；未收集项呈现为灰色虚线框，并精确标注遗漏地点（如“暮土-沉船-管道”）。
3. **BWiki 个人配置双向打通**：
   - 提取光翼数据中的 `s_xxx`（先祖永久光翼），映射到当前页面的复刻先祖列表；
   - 调用 MediaWiki 原生 `new mw.Api().postWithToken("csrf", ...)` 自动写入玩家在 BWiki 的个人收藏选项（`userjs-collectionList-travel_spirit_cn`），切回国服标签页即可看到全部先祖已被自动勾选。

## 四、 灾备体系与版本控制

1. **双重回滚通道**：
   - **Git 源码级回滚**：所有 Wikitext 与 Widget 源码同步纳管在 GitHub 仓库，出现意外可随时提取历史版本覆盖恢复；
